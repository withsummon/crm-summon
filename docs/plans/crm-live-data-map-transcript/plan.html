CRM live data, map, and transcript

Problem

The portfolio map uses a static tile source and five static markers. Geographic exposure is empty because the live facility aggregation does not populate customer region or province. The customer portal creates synthetic credit records automatically when its application list is empty; invalid linked values can fail with LinkValidationError. The live committee mode has no transcript. Some interface copy exposes infrastructure names.

Outcome

CRM pages show verified records from the existing deployed database, a token-backed 3D portfolio map, a usable committee transcript, consistent page titles, and product-facing copy without provider names. Missing source records are shown as empty states, never invented financial figures.

Approach

  • Read current deployment and database access, then inspect page queries and data availability. Reuse existing Frappe doctypes and records; seed only from verified deployed source records with explicit provenance.
  • Remove the portal's automatic sample write and its obsolete endpoint. Repair portfolio geography using linked customer address data and show loading, empty, and failure states separately.
  • Replace the portfolio tile map with Mapbox GL 3D. The browser receives only a public map token; the private transcription key remains on the server. Markers come from returned exposure regions.
  • Move committee navigation immediately under its header and stream microphone transcript during a live meeting, saving committed text against the meeting. Keep current meeting and voting flows.
  • Audit visible copy and route headers, remove provider/model names and redundant controls with no business action.

Acceptance criteria

  • Latest main is the base. Build and relevant checks pass, diff is reviewed, changes are pushed to main, and remote commit is read back.
  • Opening an empty customer portal does not write synthetic applications, facilities, or tickets and does not show LinkValidationError.
  • Portfolio regions and markers reflect actual CRM facilities and linked customer locations. Zero source records render an explicit empty state. The map renders in 3D with a valid public token and has a clear missing-token state.
  • Committee tabs are visible at the top. With a configured private transcription key, starting live capture shows partial and committed transcript, and committed text can be read back after reload. Without a key, it shows a controlled unavailable state.
  • No visible CRM copy names LLM or transcription providers or a model. Every audited route shows its title.
  • After deployment, confirm the live SHA and verify the named routes in an authenticated browser. Distinguish source/build/push/deploy/UAT evidence.

Impact and commitments

Finance figures must trace to deployed CRM records. No placeholder seed may be treated as real credit data. Credential values must never enter git or browser logs. Existing application, voting, and reporting actions must remain available.

Open constraints

The CRM runs in the Frappe bench on 72.60.78.94. The current database contains facilities and customer territories, but some older watchlist and alert records are sample data. Capital and regulatory assumptions have no verified source and must not be presented as configured policy. Production browser verification remains required after deployment.
