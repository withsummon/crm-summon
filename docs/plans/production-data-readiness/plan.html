CRM production data readiness

Problem

Production Call Logs has no stored records. The staff preview in Customer Portal resolves an arbitrary customer, so it can show zero even though related facilities exist for other customers. An initial sidebar audit also found empty calendar and notification views, plus pages with static example metrics that must not be presented as live data.

Outcome

A presenter can navigate every sidebar module using persisted operational data and honest empty states. Customer Portal shows a customer with linked records in staff preview. No financial, payment, decision, or call event is represented as real unless the database contains evidence for it.

Approach

  • Inventory sidebar routes, their data sources, empty/error states, and production record counts.
  • Fix shared customer resolution for staff preview using linked database records while retaining customer-only access controls.
  • Show related stored communication records where a call-specific record does not yet exist.
  • Replace static sample metrics with stored data where supported; keep unsupported history and transactions explicitly unavailable.

Acceptance criteria

  • Each sidebar page is opened in an authenticated production browser and its state recorded.
  • Call Logs remains accurate about the absence of voice calls and offers existing customer communication context.
  • Staff Customer Portal dashboard and its Applications/Facilities tabs read back one consistent linked customer; a customer account cannot select another customer's records.
  • No existing customer, credit decision, payment, or call history is overwritten.
  • Targeted tests, build, diff check, deployment status, and browser smoke checks are recorded separately.

Impact and commitments

Only records already stored in the existing CRM database are used. Configuration and business records remain intact. The live site is crm.withsummon.com.

Notes

Historical snapshots and external interactions cannot be inferred from current tables. Empty pages backed by such events remain accurate until verified records are imported or generated by real use.
